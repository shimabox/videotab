# 安全のしくみ

読み取りの AI に許していること・止めていること、videotab があなたのほかのファイルを書き換えないしくみ、動画のアップロードと取り込みの守り、画面が返すタブ譜のページの扱いの説明です。[README に戻る](../README.md)

読み取りは、videotab が裏で起動するあなたの Claude Code（`claude -p`）か Codex（`codex exec`）が行います。以下では、これを「読み取りの AI」と呼びます。

## 読み取りの AI に許していること・止めていること

### Claude Code

`--restricted` と `--permission-mode dontAsk` で起動します。利用者の設定（auto モードなど）は読み取りの AI に読ませません。

- モデルと推論の強さだけは起動の引数で渡します。画面か `videotab run` で選んだ値は `--model` / `--effort` で、選ばなかった項目は videotab がユーザー設定から読んだ値を `--settings`（`model` と `modelSettings` だけの JSON）で渡します。ほかの設定は渡しません。
- 読めるのは作業フォルダの中だけです。
- 書けるのは、担当の読み取り結果など決まったファイルだけです。
- 実行できるのは、`videotab check` と `videotab zoom` だけです。作業フォルダの外を指すパス（`..` や外へのリンクを含む）を渡されたり、作業フォルダの中で読み書きするファイルやフォルダが外を指すリンクだったりすると、videotab 自身が断ります（環境変数 `VIDEOTAB_CONFINE`）。
- それ以外の操作は、聞かずに拒否します。読み取りの決まり（AGENTS.md の抜粋）はプロンプトに入れて渡します。

### Codex

利用者の設定（`~/.codex/config.toml`）を読み取りの AI に読ませずに、`workspace-write` の sandbox で起動します。書き込み先の追加とネットワークは切ります。

- モデルと推論の強さだけは、画面か `videotab run` で選んだ値か、選ばなかった項目は videotab がユーザー設定から読んだ値を、起動の引数（`-m` と `-c model_reasoning_effort=...`）で渡します。ほかの設定は渡しません。
- 書けるのは作業フォルダの中だけです。`workspace-write` の sandbox は既定で `/tmp` と `$TMPDIR` にも書けるので、この 2 つを書き込み先から外します（`-c sandbox_workspace_write.exclude_slash_tmp=true` と `-c sandbox_workspace_write.exclude_tmpdir_env_var=true`）。`$TMPDIR` には、videotab 本体が Codex の最後の返答を受け取るファイルや、ほかのプログラムの一時ファイルがあるためです。最後の返答のファイルは sandbox の外の Codex 本体が書くので、受け取れます。
- 一時フォルダを外した効果を確かめた環境は macOS・codex-cli 0.158.0 です。Linux では確かめていません。
- 読み取りの AI が実行する `videotab check` / `zoom` は一時フォルダを使わず、作業フォルダの中だけに書きます。
- ファイルを読むことと、sandbox の中でのコマンドの実行は制限しきれません。

### videotab check / zoom

どちらの AI から実行した `videotab check` / `zoom` も、作業フォルダの外に触れません（環境変数 `VIDEOTAB_CONFINE`）。

- 引数のパスは、外を調べる前に断ります。`..` は字句のまま畳み、作業フォルダの中だけを 1 つずつたどってリンクの行き先を確かめます。そのため、外にファイルがあるかどうかや権限で、断りの文は変わりません。
- 中で読み書きするファイルやフォルダ（`meta.json`・`score.json`・`parts/`・`frames/`・フレームの画像・`pages/zoom/` など）が外を指すリンクなら断ります。`zoom` の出力の画像がリンクのときは、通常のファイルに置き換えて書きます。

### 同時の実行

同じ曲を、画面と `videotab run` で同時に実行することはできません（`job.lock`）。

## videotab がほかのファイルを書き換えないしくみ

読み取りの AI（特に Codex）は、作業フォルダの中にシンボリックリンクやハードリンク（別の場所を指すファイル）を作れます。AI が動画の画像に書かれた指示にだまされてそれを置いても、videotab 本体がそれをたどって作業フォルダの外に書かないようにしています。

対象は videotab 本体です。画面・`videotab run` と、その中で動く `add`・`frames`・`strip`・`pages`・`build`・`verify` が含まれ、人が直接実行したコマンドも同じです。どれも、作業フォルダに書く・消す・移すときに、作業フォルダの外を変えません。

### 種類ごとの扱い

| 種類 | 書く名前がリンクなど | フォルダが外へのリンク |
|---|---|---|
| 本体の状態と記録（`job.json`・`job.log`・`meta.json`） | 通常のファイルに置き換えて書く | —（作業フォルダの直下） |
| 生成物（楽譜・`frames/`・`pages/`・`strip/` の中身・取り込んだ動画など） | 通常のファイルに置き換えて書く | リンクを消して作り直す（先の中身は残る）。拡大の出力先は断る |
| 利用者・AI のデータ（`score.json`・`history/`・`parts/`・`readers/`） | `score.json` の雛形は無いときだけ作る。外へのリンクなら作らない | 断る |

### 細かい決まり

- 途中のフォルダは、作業フォルダの中を指すリンクならたどります。外を指していないことを確かめてから、リンクをたどらずに開き直して使います。
- 書く名前は、同じフォルダに作った一時ファイルからの付け替えで置き換えます。書く名前がリンク・ハードリンク・FIFO でも、その名前だけが置き換わり、先は変わりません。
- 本体の状態と記録（`job.json`・`job.log`・`meta.json`）と生成物（`<ID>.html`・`<ID>.alphatex`・`conflicts.json`・`timing.json`・`marks.json`・`readers/notes*`・`frames/`・`pages/`・`strip/` の中身・取り込んだ動画）は、書く名前がリンクなどなら通常のファイルに置き換えて、そのことを 1 行知らせます（コマンドは標準出力、通しの実行では `job.log`）。`job.log` がフォルダのときは置き換えず、標準エラーに出します。
- 生成物のフォルダ（`frames/`・`pages/`・`strip/`）が外を指すリンクなら、リンクを消して作り直します（リンクの先の中身は残ります）。
- `frames/` がリンクのとき（中を指すものも）は、リンクの先の中身を見ずに作り直しの対象にします。`videotab frames` は `--force` なしでも作り直し、通しの実行と画面は切り出し済みの画像として使い回しません。
- `zoom` の出力のフォルダ（`pages/zoom/`）が外を指すときは断ります。
- 利用者・AI のデータ（`score.json`・`history/`・`parts/`・`readers/`）は、フォルダが外を指すリンクなら断ります。`score.json` の雛形は無いときだけ作り、外へのリンクなら先が無くても作りません。前回の読み取り結果は、リンクをリンクのまま `history/` へ移します。
- 読み取りの途中で AI が `job.json` を差し替えても、通しの実行は始めに読んだ状態を持って進むので、段の結果と失敗は記録されます。
- 外部のプログラム（ffmpeg）と動画の取り込み（`add`・画面のアップロード）は、作業フォルダの親（画面・`videotab run` の置き場。既定は `work/`）に作る本体専用の一時フォルダ `.videotab-tmp-*` に書き出し、書き終えてから作業フォルダへ付け替えで取り込みます。読み取りの AI は置き場に書けないので、書いている間に差し替えられません。一時フォルダは成功でも失敗でも消し、途中で止まって残ったもの（送っている途中で止まったアップロードを含む）は画面の起動時に消します。
- `videotab frames` は、作業フォルダの動画が外を指すリンクなら、ffmpeg に渡さずに断ります。
- フォルダを消すとき（切り出しのやり直し、タブ譜が写っていないときの削除、一時フォルダの後始末）は、リンクはリンクだけを消します。フォルダは Python の fd を使う `shutil.rmtree`（`dir_fd` 付き）で消すので、消している途中に中のフォルダをリンクへ差し替えられても外をたどりません。
- 本体が書くファイルやフォルダを自分でリンクにしている場合は、通常のファイルやフォルダに置き換わります。作業フォルダごと別の場所に置く使い方（`work/<ID>` をリンクにする、`--root`）は使えます。
- 本体が読むときはリンクをたどります（対象は書く・消す・移すことだけです）。画面の `/files/` は、作業フォルダの外を指すリンクと、外のファイルとのハードリンクを返しません。

## 動画のアップロードと取り込み

画面は、動画ファイルを `POST /api/uploads` で受け取ります（本文は動画のバイト列そのもの、ファイル名・読み取りの設定と、任意の題名・作成者・元動画のページはクエリ。画面が送るのはファイル名と読み取りの設定だけ）。`videotab add` / `videotab run 動画.mp4` も、同じ取り込みの手順を使います。

### 本文を読む前に断るもの

| 条件 | 応答 |
|---|---|
| 画面からの操作でない（見出し `X-Videotab` が無い・別の出どころ・Host が 127.0.0.1 / localhost でない） | 403 |
| 本文の大きさ（`Content-Length`）が無い | 411 |
| `Content-Length` が数字でない | 400 |
| 4 GB を超える | 413 |
| 拡張子（.mp4 .m4v .mov .webm .mkv .avi 以外）・読み取りの AI・モデルと推論の強さ・元動画のページ・題名・作成者の誤り | 400 |

- 元動画のページは、空か、`https://` で始まり空白を含まない 2000 文字までのものだけを受け付けます。題名と作成者は、改行などの制御文字を含まない 200 文字までです。
- 止める・やり直すの JSON の本文は 1 MB までです。曲を作る口は `POST /api/uploads` だけです。

### 受け取りと確かめ

- 本文はメモリに読まず、置き場の一時フォルダ `.videotab-tmp-*` へ 1 MB ずつ、`Content-Length` ちょうどの長さだけ書き写します。足りなければ断り、一時フォルダを消します。
- 書き写した動画は ffprobe で確かめ、映像が入っていなければ断ります（400）。ffprobe が無いなどで確かめられないときは 500 で理由を返します。
- 確かめてから新しい ID の作業フォルダを作り、`video.<拡張子>` へ付け替えます。そのあとの失敗では、作った作業フォルダを消します。一時フォルダは成功でも失敗でも残しません。
- 長い書き写しの間も、画面の一覧やほかの操作は止まりません（順番待ちへの登録だけを排他にします）。
- `meta.json` には元のファイル名だけを残し、パスは残しません。通しの実行は、作業フォルダの外のファイルを取り込み直しません（`meta.json` や `job.json` は読み取りの AI も書き換えられるので、そこに書かれたパスを開かないためです）。
- 元動画のページは、画面の詳細とタブ譜のページに出すときにも `https://` で始まるかを確かめ直します（`meta.json` を書き換えられても、`javascript:` などのリンクを出しません）。

### ffprobe / ffmpeg の入力の制限

中身が再生リストなどの「動画」を渡されても、ネットにも、指定した動画ファイル以外のローカルファイルにも触れないよう、ffprobe（取り込み時の確認）と ffmpeg（画像の切り出し）の両方で、入力の前に次を付けます。どちらも入力の解析より前に効きます。

```
-protocol_whitelist file -format_whitelist mov,mp4,m4a,3gp,3g2,mj2,matroska,webm,avi
```

- `-protocol_whitelist file`: 読むのはローカルのファイルだけです（http などには出ません）。
- `-format_whitelist`: 入れ物は mov/mp4 系・matroska/webm・avi だけです。concat や hls などの再生リストとしては解釈しないので、その中に書かれた別のファイルや URL を開きません。
- 取り込み時は、ffprobe が報告した入れ物の名前も確かめます。
- 確かめた環境は macOS・ffmpeg 9.0 です（concat の再生リストが別のローカルファイルを開かないこと、手元の HTTP サーバーへ届かないことをテストで確かめています）。

## 画面が返すファイル（/files/）

画面は、タブ譜のページ（`/files/<ID>/<ID>.html`）と、作業フォルダの中の画像などを `/files/` で返し、画面の中や別のタブで表示します。作業フォルダには読み取りの AI も書けるので（Codex は `<ID>.html` そのものも書き換えられます）、保存された HTML は返さず、`/files/` のページは画面から切り離して動かします。

### 保存された HTML は返さない

読み取りの AI が書いた HTML を画面が開くと、そのページのスクリプトは、利用者のブラウザから外へ通信できます（下の sandbox は、ページからの通信までは止めません）。Codex はネットワークを切って起動しますが、手元のファイルは読めるので、読んだ内容を HTML に入れて画面に開かせれば、外へ送れてしまいます。そこで、読み取りの AI が書ける HTML は、ページとして返しません。

- タブ譜のページは、保存された `<ID>.html` ではなく、`<ID>.alphatex` から本体が要求のたびに組み立てて返します。`<ID>.alphatex` と `meta.json` はデータとして読み、中身はページの中で文字として扱います。`videotab build` が書く `<ID>.html` と同じ内容です（作った日時だけ、`<ID>.alphatex` の更新日時になります）。
- `<ID>.alphatex` が無い曲には、タブ譜のページがありません（`<ID>.html` があっても返しません）。4 MB を超える `<ID>.alphatex` からも組み立てません。
- ほかの `.html` は返しません。`/files/` がそのまま返すのは、`.png`・`.jpg`・`.alphatex`・`.md` だけです。

### 画面から切り離して動かす

- `/files/` のすべての応答に、次の見出しを付けます。画面の中でタブ譜を表示する iframe にも、同じ値の `sandbox` 属性を付けます。

  ```
  Content-Security-Policy: sandbox allow-scripts allow-downloads allow-modals allow-popups allow-popups-to-escape-sandbox
  ```

- 与える許可は、タブ譜の機能に要るものだけです。

  | 機能 | 許可 |
  |---|---|
  | 描画・再生 | `allow-scripts` |
  | Guitar Pro / MIDI / alphaTex のダウンロード | `allow-downloads` |
  | 印刷 / PDF | `allow-modals` |
  | 元動画・alphaTab へのリンク（別のタブで開く） | `allow-popups`・`allow-popups-to-escape-sandbox`（開いた先のサイトは sandbox の外で普通に動きます） |

- 画面と同じ出どころ（`allow-same-origin`）、フォームの送信（`allow-forms`）、最上位の画面の移動（`allow-top-navigation` など）は許しません。そのため、`/files/` のページは、画面の中の iframe・別のタブ・URL の直接入力のどの開き方でも、画面とは別の出どころ（opaque origin）で動きます。
- 画面のすべての応答に `X-Content-Type-Options: nosniff` を付け、ブラウザに中身の種類を推測させません。

### /files/ のページからできないこと

- 曲の追加・やり直し・削除。ページからの POST / DELETE は `Origin` が `null` になるので、画面からの操作として受け付けません。画面からの操作の見出し（`X-Videotab`）を付けるには、ブラウザが先に事前確認（OPTIONS）を送りますが、画面はこれに応じないので、本番のリクエストは送られません。画面はどの応答にも `Access-Control-Allow-*` を付けません。
- 画面の情報を読むこと。GET のリクエストは届きますが、応答をページから読めません。GET で変わるものはありません。
- 画面の中に表示したときに、外側の画面に触れること。最上位の画面を別のページに移すこと。
- ページから開いた別のウィンドウも、画面と同じ出どころにはなりません（`/files/` のページなら、また sandbox の下で動きます）。

### 変わること

- 画面の中や別のタブで開いたタブ譜では、自動スクロールの選択がブラウザに記憶されません。別の出どころで動くため、ブラウザの保存の場所（localStorage）を使えないからです。ページを開いている間は、選択どおりに動きます。
- 別の出どころでは、再生の音を作る部品（AudioWorklet）を読み込めないブラウザがあります（Safari）。そのため、タブ譜のページは、別の出どころで動くとき（`/files/` のページ、`file://` で開いたとき）だけ、古い方式（ScriptProcessor）で音を出します。それ以外で開いたときは AudioWorklet で音を出します。Chrome・Safari・Firefox で、画面の中でも別のタブでも再生できることを確かめています。
