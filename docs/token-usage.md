# AI の利用量の目安

読み取りで Claude Code / Codex がどれくらいのトークン（AI が読み書きする文字の量の単位）を使うかの目安です。実際に書き起こしたときの記録から数えました。[README に戻る](../README.md)

利用枠への響き方は、サービスと契約によって違います。ここの数は目安として使い、利用枠と料金は各サービスで確かめてください。

## 1 曲あたりの量

入力は、AI が読んだ量です。前のやりとりを読み直す分（キャッシュ）も含みます。出力は、AI が書いた量です。

| 素材 | 曲の大きさ | 入力（うちキャッシュ） | 出力 | 読み取りの時間 |
|---|---|---|---|---|
| 画面のタブ譜の動画 | 1.5〜6.5 分、65〜280 小節 | 160〜630 万（86〜93%） | Claude Code 5.7〜10.5 万、Codex 1.2〜2.9 万 | 4〜14 分 |
| 紙を撮った動画（推論の強さ high） | 1.5 分、107 小節 | 704 万（92%） | Claude Code 17.5 万 | 10 分 |
| 紙の楽譜（PDF・画像 ZIP） | 1〜3 ページ、24〜47 小節 | 43〜101 万（81〜87%） | Claude Code 1.2〜4.2 万、Codex 0.7〜1.0 万 | 2〜4 分 |
| TAB のない楽譜 | 1 ページ | 6 万（73%） | 0.2 万 | パートの洗い出しで止まる |

- 量は、ほぼ曲の長さ（小節の数）に比例します。1 小節あたりの入力は、画面のタブ譜の動画で 1.2〜4.7 万、紙の楽譜で 1.4〜2.3 万です。
- 入力の大部分（8〜9 割）はキャッシュです。新しく読む分は、入力の 1〜2 割です。
- 出力は、どの素材でも Codex のほうが Claude Code より少なく出ました。
- 紙の楽譜は、書き起こしの前にパートの洗い出しで AI を 1 回起動します。その分は入力が Claude Code で約 6 万、Codex で 9〜13 万で、上の表に含めています。
- 測った環境: Claude Code は claude-opus-5-5、Codex は gpt-6.1-sol です。推論の強さは、画面のタブ譜の動画が medium（Codex の 1 曲だけ high）、紙を撮った動画と紙の楽譜が high です。

## 量が増えるとき

- **やり直し**: 「読み取りからやり直す」は、読み取りを 1 回分まるごと使い直します。曲の情報の保存（「保存してタブ譜に反映」）は組み立てからやり直すだけなので、AI を使いません。
- **推論の強さ**: 強いほど、入力も出力も増えます（[読み取りのモデルと推論の強さ](model-settings.md)）。
- **重ねて読む分**: 長い曲は読み手を分けます。境目のページは隣り合う 2 人が読むので、その分だけ増えます。

## 自分で確かめる

- **Claude Code**: `~/.claude/projects/` の下に、作業フォルダのパスの記号を `-` にした名前のフォルダがあります。その中の `*.jsonl` が起動ごとの記録です。AI の返事ごとの `message.usage` の値を足すと、量がわかります。入力は `input_tokens`・`cache_creation_input_tokens`・`cache_read_input_tokens` の合計です。同じ返事が何行かに分かれて出るので、`message.id` で重複を除きます。
- **Codex**: `~/.codex/sessions/年/月/日/rollout-*.jsonl` が起動ごとの記録です。先頭の `session_meta` の `cwd` が作業フォルダのものを選びます。最後の `token_count` の `total_token_usage` が、その起動の合計です（`input_tokens` はキャッシュを含み、うちキャッシュの分が `cached_input_tokens`）。
- Codex が終わりに表示する「tokens used」は、キャッシュから読んだ入力を数えていません。そのため、上の表の値よりずっと小さく出ます。
