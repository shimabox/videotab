# コマンド

段ごとにコマンドを 1 つずつ動かす方法と、コマンドの一覧、作業フォルダの中身、セットアップで行うことの説明です。[README に戻る](../README.md)

コマンドは、videotab のフォルダの中で実行します。

## コマンドを 1 つずつ使う

紙の楽譜（写真・PDF・画像 ZIP・紙を撮った動画）の流れと、パートの選び方は [紙の楽譜から書き起こす](paper.md) を見てください。

```sh
uv run videotab add 動画.mp4                  # 新しい作業フォルダ work/XXXX/ に取り込み、ID（XXXX）を表示
uv run videotab frames XXXX                   # 1 秒 1 枚の画像に
uv run videotab strip XXXX                    # タブの帯と弦の線の位置を検出
uv run videotab pages XXXX                    # ページに分けて拡大画像を作る
# ここで AI が拡大画像を読み、work/XXXX/parts/*.json に小節ごとの alphaTex を書く
uv run videotab check XXXX                    # 拍数・タイ・記法の検査
uv run videotab build XXXX                    # つないで work/XXXX/XXXX.html と .alphatex を出力
uv run videotab verify XXXX --mark 10=57      # 繰り返し・テンポを展開した時刻を動画と比べる
```

- `XXXX` は `add` が表示する ID です。`add` は続けるコマンドを `videotab frames <作業フォルダのパス>` の形で表示します。ID の代わりに作業フォルダのパスを渡すと、`--root` で作業フォルダを置く場所（既定は `work/`）を変えたときも同じ作業フォルダを指せます。
- `-` で始まる名前のファイルは、`uv run videotab add ./-x.mp4` のようにパスで渡します。

画像の読み方の決まりは [AGENTS.md](../AGENTS.md) にあります。

## コマンド一覧

終了コードは、コマンドが終わるときに返す番号です（0 は成功、1 は失敗）。下の表の 3 は、タブ譜が写っていなかったことを表します（通しの実行では、その曲は失敗になります）。4（パートの選択待ち）と 5（紙を撮った動画）は、失敗ではなく、決まった理由で止まったことを表します。

| コマンド | 内容 |
|---|---|
| `serve [--port N] [--root DIR]` | 動画ファイルを送るとタブ譜まで作る画面を開く |
| `run FILE\|ID [--title T] [--creator C] [--source-url U] [--engine claude\|codex] [--model M] [--effort E] [--step 段] [--root DIR]` | 取り込みからタブ譜の出力までを通しで実行（画面なし）。動画ファイルなら新しく取り込み、既存の作業フォルダの ID ならその続きから進める。`--title` などは新しく取り込むときだけ、`--step` は既存の ID のときだけ使える。`--model` / `--effort` は読み取りのモデルと推論の強さ（[読み取りのモデルと推論の強さ](model-settings.md)）。写真・PDF・ZIP・画像フォルダも渡せる（紙の楽譜）。紙の楽譜は `--part` を省くとパートを洗い出して止まり（終了コード 4: パートの選択待ち）、`--part 名前 [--strings 4\|6]` で続ける。`--paper` は動画を紙の楽譜として取り込む、`--step strip --paper` / `--screen` は取り込み済みの動画の楽譜の種類を切り替える |
| `add FILE [--title T] [--creator C] [--source-url U] [--paper] [--part P] [--strings 4\|6] [--root DIR]` | 動画ファイル（.mp4 .m4v .mov .webm .mkv .avi、4 GB まで）を ffprobe で確かめ、新しい作業フォルダに `video.<拡張子>` として取り込む。題名（既定はファイル名）・作成者・元動画のページ（https:// で始まるもの）・元のファイル名・幅と高さ（回転を適用した向き）・長さを `meta.json` に記録 |
| `frames ID [--from DIR\|ZIP] [--fps N]` | ffmpeg で一定間隔の画像に。既存の画像フォルダや画像の ZIP も取り込める（ファイル名が `NNNN_MMmSSsmmm.png` なら、その時刻を使う） |
| `strip ID [--band Y0 Y1]` | タブの帯の位置と 1〜6 弦の線の上下の位置を検出し、確認用の画像を出す。ページによって段の上下の位置が動く動画では、切り出したすべてのフレーム（動画から切り出した 1 枚 1 枚の画像）の線の位置を記録し、帯は線が動く範囲の全体を含む（確認用の画像は、段がいちばん上と下にあるフレームを含む）。線が見つからなければ終了コード 3（タブ譜が写っていない）で止まる（通しの実行ではこのとき動画と画像を消す。`--band` で決めた帯は、通しの実行でやり直しても使われる）。紙を撮った動画と判定したら、紙の楽譜の曲に切り替えて終了コード 5（紙を撮った動画）で止まる（`--band` 指定時や、種類を利用者が決めた曲では判定しない） |
| `pages ID [--threshold T]` | 帯の中身の切り替わり（ページ送り・横スクロール）でページに分け、弦の番号付きの拡大画像と一覧（`index.md`）を作る。段の位置が動く動画では、拡大画像の印と一覧の線の位置はページごとの位置で、位置が変わる所でもページを区切る |
| `paper ID [--part P] [--strings 4\|6]` | 紙の楽譜の曲の候補の一覧だけを作る（AI は起動しない）。パートを省くと保存済みの指定を使う |
| `zoom ID FRAME` | 1 フレームをページと同じ倍率で拡大（演奏位置の枠に隠れた数字の確認など）。印はそのフレームの線の位置に付く |
| `check ID\|FILE` | 小節ごとの長さ、つながり先のないタイ、記法のくせを検査 |
| `build ID` | 読み取り結果をつなぐ。重ねて読んだ小節の食い違い・抜け・検査の誤りがあれば一覧にして止める |
| `verify ID [--mark 小節=秒]` | 繰り返し・テンポ変化を展開した各小節の開始時刻を出し、動画で見た時刻と比べる |
| `--version` | videotab の版を表示（画面では見出しの横に出る） |

カメラで画面を撮影した動画では、水平な線が見つからないか弱い場合に、約 ±2 度までの傾きを探します。薄い線は周りの背景との明るさの差で見て、照明のむらの影響を抑えます。補正を採用した動画では、フレームごとの傾き・上下の位置・弦の間隔の伸縮を `meta.json` に記録し、`pages` と `zoom` の画像を同じ水平な位置にそろえます。手ぶれだけではページを区切りません。`strip/check_*.png` は元画像に傾いた線の位置を示すので、検出が合っているか確認できます。`--band` を指定した場合も、この補正を使います。画面を斜めから撮って形が台形に大きく歪んだものや、横方向の手ぶれには対応していません。ぼけや映り込みで数字を読み違えることがあるため、可能なら画面録画の動画を使ってください。

`pages` の自動判定は、帯全体の差に加えて、数字の周りの小さな変化も調べます。演奏位置の枠のような長い直線はこの小さな変化の比較から除き、同じ配置でフレットの数字だけが変わるページを拾います。`--threshold T` を指定した場合は、この比較を使わず、帯全体の差と横スクロールだけで区切ります。

## 作業フォルダ

`work/<ID>/` にまとまります。ID は、動画のファイル名の英数字と、ランダムな 6 文字（0〜9 と a〜f）からなる名前です（例 `practice-1a2b3c`。ファイル名に英数字が無ければ `video-1a2b3c`）。`work/` は Git（ソースの変更を記録する道具）の記録から外してあるので、取り込んだ動画などが videotab のソースと一緒に記録されることはありません。

| パス | 中身 |
|---|---|
| `video.<拡張子>` | 取り込んだ動画 |
| `meta.json` | 動画の題名・作成者・元動画のページ・元のファイル名・幅と高さ（回転を適用した向き）・長さ、検出した帯と線の基準の位置（段の位置が動く動画では、フレームの区間ごとの基準からのずれも。カメラ撮影の補正を採用した動画では、フレームごとの傾き・上下のずれ・弦の間隔の伸縮・線を検出できたかも） |
| `frames/` | `NNNN_MMmSSsmmm.png`（フレーム番号・時刻） |
| `strip/` | 帯と線の確認用の画像 |
| `pages/` | ページごとの拡大画像、`pages.json`、`index.md` |
| `parts/*.json` | 読み取り結果 `{"小節番号": "alphaTex"}`（分けて読んだら、まとまりごとに 1 ファイル） |
| `score.json` | 曲名・副題・動画の作成者・テンポ・拍子・チューニング・カポ |
| `resolve.json` | 食い違いを解いた小節 |
| `marks.json` | 動画で見た小節の時刻 `[[小節, 秒], ...]` |
| `readers/` | 読み取りの AI ごとの報告と「ページ → 最初の小節」 |
| `job.json` / `job.log` | 通しの実行の段ごとの状態とログ |
| `<ID>.html` / `<ID>.alphatex` | できあがり |

画面の「この曲を消す」は、`work/<ID>/` をフォルダごと消します（動画・画像・タブ譜・読み取りの結果、前回までの読み取り結果の `history/` も含みます）。元に戻せません。実行中・順番待ちの曲と、`videotab run` が動いている曲は消せません。

## セットアップで行うこと

`make setup`（中身は `./setup.sh`）は、次を順に行います。何度実行しても構いません（入っているものは飛ばします）。

1. uv（Python と必要な部品をそろえる道具）があるか確かめます。無ければ公式の導入の手順を実行するか聞き、同意したときだけ入れます。
2. ffmpeg と ffprobe があるか確かめます。ffmpeg は動画を画像に切り出すソフトで、ffprobe は取り込む動画の中身を確かめるソフトです（ffmpeg と一緒に入ります）。無ければ、Mac で Homebrew があるときは `brew install ffmpeg` を実行するか聞き、それ以外は入れ方を表示して止まります。
3. `uv sync --locked` で、Python 3.11 と videotab が使う部品を、決まった版のとおりに入れます。
4. 読み取りに使う Claude Code（`claude`）か Codex（`codex`）があるか確かめます。ログインが要るので、これは入れません。

uv と ffmpeg を自分で入れてあれば、`uv sync` だけでも同じです。
