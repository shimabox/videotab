videotab

動画ファイルを渡すと、画面のタブ譜が 1 枚の楽譜になる

「TAB 譜付き」の演奏動画は、画面に写るタブ譜が数小節ずつ流れていきます。videotab は、手元に用意した動画ファイルからそれを最初から最後まで拾い集めて、再生もダウンロードもできる 1 枚の楽譜にまとめます。画像を扱う部分は videotab 自身が受け持ちます。数字やリズムを読む部分は、あなたの Claude Code か Codex（以下「AI」）が受け持ちます。

TAB

上から 1 弦〜6 弦。数字は押さえるフレット。これを「どの弦の、何フレットを、どの長さで」の並びとして読み取ります。

全体の流れ

7 つの段を順に進む

画面で動画ファイルを選んで「タブ譜を作る」を押すと、この 7 段が自動で進みます。途中で失敗しても、その段からやり直せます。

videotab（画像処理とルール） AI（Claude Code か Codex）
  1. videotab動画の取り込み手元の動画ファイルを確かめて作業フォルダへadd
  2. videotab画像の切り出し1 秒に 1 枚の静止画frames
  3. videotab帯と線の検出タブ譜の場所と 6 本の弦の位置strip
  4. videotabページ分け画面が切り替わるごとの拡大画像pages
  5. AI読み取り小節ごとの楽譜データ（alphaTex）read
  6. videotabタブ譜の組み立て検査して 1 枚の楽譜（HTML）にbuild
  7. videotab時刻の照合動画の時刻と楽譜の時刻を比べるverify

AI が受け持つのは 5 の「読み取り」だけです。取り込み・切り出し・検出・組み立て・照合は、決まったルールで videotab が行うので、何度やっても同じ結果になります。

段ごとの中身

それぞれの段で何をしているか

1・2

取り込みと切り出し

videotab ＋ ffprobe・ffmpeg
  • 手元の動画ファイル（.mp4 .m4v .mov .webm .mkv .avi、4 GB まで）を、画面のアップロードか videotab add で受け取ります。ffprobe で映像が入っていることを確かめてから、新しい作業フォルダに取り込みます。
  • ffmpeg で 1 秒に 1 枚の画像にします。ファイル名に番号と時刻が入ります（例 0154_02m33s000.png）。
  • ffprobe と ffmpeg は、ローカルのファイルを動画の入れ物としてだけ読みます。再生リストなどとして解釈しないので、ネットにも、ほかのファイルにも触れません。
  • 手元の画像フォルダや、komadori で書き出した ZIP も取り込めます。

なぜ解像度が大事か　360p だとタブの数字が数ピクセルしかなく、6 と 8 を見分けにくいためです。1080p ほどの動画を使ってください。

3

帯と線の検出

videotab

画像を 1 行ずつ見て、「上と下の両方より濃い画素」が横にどれだけ並ぶかを数えます。弦の線は横いっぱいに続くので、その行だけ値が高くなります。

  • 等間隔に並んだ 6 本の山をタブ譜とみなします。五線（5 本）は混ざりません。
  • タブの線の間の地の色が続く範囲を「帯」とし、小節番号や五線もその中に入れます。
  • 白地に灰色の薄い線、暗い地に明るい線のどちらにも対応します。
4

ページ分け

videotab

帯の中の「インク」（地の色と大きく違う画素）を、今のページの最初の画像と比べます。差が大きくなったら次のページです。

  • ページ送り: 帯全体が一気に変わるので、差がはっきり大きい。
  • 横スクロール: 差は中くらいですが、帯を横にずらして重ねると差が縮む。これでスクロールだと分かります。
  • 演奏位置の枠や、今弾いている音の色替え: 差は一部だけで、ずらすとかえって差が広がるので、ページとは数えません。

ページごとに、弦の線の間隔が約 30px になるまで拡大し、左の余白に弦の番号を書き込みます。数字がどの弦に乗っているかを取り違えないためです。

なぜ弦の番号を書き込むか　手で読んでいたとき、線 1 本ずれて別の弦と読む間違いが実際に起きたからです。

5

読み取り

AI（Claude Code / Codex）

拡大画像を見て、小節ごとに「どの弦の何フレットを、どの長さで」を楽譜データ（alphaTex）に書きます。リズムは五線の音符か、タブの下の棒と連桁の本数で読みます。

(5.5 0.6).8  (0.6).8  (7.5 0.6).8  …
5.5
5 弦の 5 フレット（フレット.弦）
(5.5 0.6)
同時に鳴らす音（和音）
.8
8 分音符。1 小節の合計が拍子ちょうどになるよう読む

なぜここだけ AI か　数字の場所は画像処理で分かりますが、リズム（付点・休符・連符）や記号（繰り返し、パームミュート、チョーキング）の意味を決めるには、文脈を見た判断が要るからです。

6

タブ譜の組み立て

videotab
  • 分けて読んだ結果をつなぎ、1 小節ずつ検査します。1 小節の長さが拍子と合うか、タイ（前の音から伸ばす印）のつながり先があるか、書き方のくせがないか。
  • 抜けた小節や、重ねて読んだ小節で答えが食い違う所があれば、先へ進まずに AI に直させます。
  • 通れば、楽譜を描く alphaTab を埋め込んだ 1 ファイルの HTML にします。オフラインでも表示でき、再生もできます（再生の音源データだけはネットから読みます）。
7

時刻の照合

videotab

繰り返し記号（「7x」など）とテンポの変化を展開して、各小節が何秒目に鳴り始めるかを計算します。それを「このページが出たのは何秒目か」と比べて、ずれがないかを確かめます。

何が分かるか　繰り返しの回数やテンポの読み違いは、音だけ見ても気づきにくいのですが、時刻がずれるので見つけられます。

読み取りの分担

ページを分けて同時に読み、境目は重ねて読む

長い曲は、ページをいくつかのまとまりに分け、まとまりごとに AI を起動して同時に読ませます（最大 4 つ）。となり合うまとまりは境目のページを両方で読むので、2 つの答えが合うかどうかで読み違いに気づけます。

食い違いや抜けは、まとめ役の AI（つなぎ目の問題を解くために別に起動する AI）が画像を見直して解きます。決め手は、数字がどの線に乗っているか（弦の位置）と、和音として自然か（構成音・キー）です。解いた答えは最初の読み取り結果とは別に残るので、あとから見直せます。

AI は最後に短い報告（書いた小節、自信のない所、曲の構成、直した小節）を日本語で返します。画面では、この報告を見出し・箇条書き・太字・コードを整えて表示します。報告の中に HTML が書かれていても、文字として出るだけで動きません。

安全の仕組み

AI には、できることを絞っている

読み取りでは、videotab があなたの Claude Code / Codex を裏で起動します。普段の設定のまま動かすと何でもできてしまうので、起動のしかたで、できることを絞っています。

許していること

  • その曲の作業フォルダ（曲ごとに画像や結果を置くフォルダ）の中のファイルを読む
  • 決まった結果のファイルにだけ書く
  • 検査（videotab check）と拡大（videotab zoom）を実行する。この 2 つも、作業フォルダの外には触れません

止めていること

  • 作業フォルダの外のファイルを読む・書く
  • ほかのコマンド（python、cat など）を実行する
  • あなたの普段の設定（自動で許可するモードなど）を引き継ぐ。モデルと推論の強さだけは、画面で選んだ値か、選ばなければ普段の値を使います

Claude Code では、止めていることを聞かずに拒否します。Codex では、書き込みを作業フォルダの中に限りますが、ファイルを読むことやコマンドの実行までは止めきれません。Codex の sandbox が既定で書ける一時フォルダ（/tmp・$TMPDIR）も、書き込み先から外します（確かめたのは macOS で、Linux では確かめていません）。どちらも API キーは使わず、あなたが手元でログインしている Claude Code / Codex の利用枠で動きます。画面で選んだモデルと推論の強さはその曲の読み取りだけに使い、普段の設定は書き換えません。

videotab も、あなたのほかのファイルを書き換えない

AI（特に Codex）は、作業フォルダの中に「別の場所を指すファイル」を置けます。AI が動画の画像に書かれた指示にだまされてそれを置いても、videotab があなたのほかのファイルを書き換えることはありません。

できあがったタブ譜のページも作業フォルダの中にあり、AI が書き換えられます。そのため画面は、タブ譜のページを画面とは切り離して（別の出どころとして）表示します。ページに与えるのは表示・再生・ダウンロード・印刷・リンクに要る許可だけで、ページの中から曲の追加・やり直し・削除はできません。画面の中や別のタブで開いたときは、自動スクロールの選択は記憶されません。

動画を受け取る口は、画面からの操作だけを受け付けます。大きさや形式は中身を読む前に確かめ、受け取った動画は本体専用の一時フォルダで確かめてから取り込みます。

起動のしかたや、ほかのファイルを守るしくみの詳しい説明は 安全のしくみ（docs/safety.md） にあります。

使い方

画面から使う・コマンドで使う

# 画面を開く（http://127.0.0.1:8765/ 。手元のマシンの中だけで動く）
uv run videotab serve

# 画面を使わずに、同じ流れを通しで
uv run videotab run 動画.mp4

# 読み取りのモデルと推論の強さを選ぶこともできる（画面でも選べる。選ばなければ普段の設定）
uv run videotab run 動画.mp4 --model opus --effort max

# 段ごとに動かすこともできる（ID は add が表示する）
uv run videotab add 動画.mp4 / frames ID / strip ID / pages ID / check ID / build ID / verify ID
作業フォルダ work/<ID>/中身
video.*取り込んだ動画
frames/1 秒 1 枚の画像
pages/ページごとの拡大画像と一覧（index.md）
parts/AI の読み取り結果（分けて読んだまとまりごと）
resolve.jsonまとめ役の AI が解いた小節
readers/AI の報告と、ページごとの最初の小節の番号
job.json / job.log段ごとの進み具合とログ
<ID>.htmlできあがった楽譜

動画・画像・楽譜は、手元の work/ フォルダに保存されます（git の管理外なので、リポジトリには入りません）。要らなくなった曲は、画面の「この曲を消す」で作業フォルダごと消せます（元に戻せません）。

詳しい使い方は README と、画面の使い方・読み取りのモデルと推論の強さ・コマンド にあります。

免責事項

  • 書き起こしは画像処理と AI による自動のもので、誤りを含むことがあります。
  • 動画・画像・書き起こしたタブ譜には、楽曲や元の動画・タブ譜の作り手の著作物が含まれます。
  • 私的な練習の範囲で使い、公開・再配布・販売をしないでください。
  • 読み取りは、あなたの Claude Code / Codex の利用枠を使います。強い設定ほど利用枠を多く使い、時間もかかります。
  • すべての項目は README の免責事項 にあります。
